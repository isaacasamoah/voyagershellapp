Topic + relationship rule · establish knowledge → settle topics → Jev checks links → notify
  1. 1 · Jev matches

    Existing topic IDs, names and scopes. Several matches, no match, or uncertain.

  2. 2 · Sol composes

    On no-match, Sol also sees the catalogue. Suggest existing IDs or propose a new subject. Evidence does not support the knowledge? Keep the attempt for inspection; do not publish it or create a topic from it.

  3. 3 · Jev rechecks

    Only for a new proposal or disputed match: same subject and scope as an existing topic? Ambiguous match → keep a visible pending candidate, with the reason. Do not guess a match or create a topic; reassess when more context or review is available.

  4. 4 · Harness settles topic IDs

    Reuse or create atomically. If the catalogue changed since the last topic check, ask Jev about additions or changed definitions before retrying. This saves the topic, not the final knowledge update.

  5. 5 · Jev judges relationships

    Compare knowledge statements, conditions and evidence. Decisions may contradict; discoveries may support or challenge. Shared topics alone do not establish a link.

  6. 6 · Harness records + routes

    Save knowledge and judged links. Send topic updates; use the links to notify affected authors and responsible resolvers. One packet per recipient, with the reason.

Agreed existing matches skip step 3. A name match alone is insufficient. This small trial supplies the full catalogue; an incomplete catalogue cannot justify creating a topic. Pending candidates do not pause other agent work. No relationship is also a valid outcome; normal topic updates can still be sent. Supersession requires an explicit resolution.

Jev makes typed judgments. Sol writes evidence-linked statements. The harness stores, routes and records explicit resolutions.
